# Open questions

Gaps, unresolved contradictions, and sources worth finding. Lint passes add to this list. Up: [[syntheses]].

## Open questions
1. **Portability.** Will loop *definitions* become portable across tools? TNS predicts the vendor who does it *"will take pole position"* ([[src-tns-loop-engineering]]). Huntley's view that prompts are operator-specific cuts against it ([[src-huntley-ralph]]). *Lead (2026-10-19):* [[openprose]] claims harness-agnostic contracts, but its benchmarks are *"openly pending"* ([[src-openprose]]). [[ouroboros]] runs one Seed format on 14 runtimes, but publishes no cross-runtime results ([[src-ouroboros]]). See [[loop-primitives]].
2. **Budget-based termination.** *Partly answered (2026-10-15):* pstack's Orchestrate stops spawning at ~70% of budget ([[src-inside-pstack-report]]). This is a soft drain. *Update (2026-10-19):* omp's `/goal` has a hard **token** budget that flips the goal to `budget-limited`, excluding cache reads ([[src-omp]]). There is still no source on dollar kill switches. See [[budgets-and-cost]] and [[termination]].
3. **`/goal` limits.** What happens when a goal is unreachable? Are there turn caps? See [[claude-code-goal]]. *For omp (2026-10-19):* a token budget, no runtime turn cap, and an attempt cap required only in the objective text ([[src-omp]]).
4. ~~**Idempotency.**~~ **Partly answered (2026-10-12):** Tan's *Make Operations Idempotent* principle gives a test and patterns ([[src-tan-pstack-loop-principles]]). What's still missing is a worked failure case for external side effects (messages, tickets). See [[idempotency]].
5. **Existing codebases.** Huntley says greenfield only. Osmani runs loops daily on existing repos. What separates the two cases? See [[ralph-loop]].
6. **Multi-agent coordination.** Hierarchical subagents are widely endorsed, but peer agent teams are contested. See [[orchestrator-workers]]. *Update (2026-10-27):* Anthropic now argues for folding many subagents back into one loop ([[src-anthropic-fold-subagents]]). See #30 and [[folding-subagents]].
7. **In-session vs fresh-context loops.** Pocock says loops inside one session (the Anthropic Ralph plugin) slide into the dumb zone ([[src-pocock-ralph-plugin]]). Do Claude Code's `/loop` and `/goal` have this problem, or do they clear or compact between iterations? See [[smart-zone]], [[claude-code-loop]] and [[claude-code-goal]].
8. **Where is the dumb zone?** About 40% of the window ([[src-pocock-ralph-plugin]]) vs 125K–150K tokens ([[src-pocock-ai-coding-dictionary]]). Is it a fraction of the window or an absolute count? Does it vary by model?
9. **Terminology.** "Backpressure" / "feedback loop" vs "automated check" ([[src-pocock-ai-coding-dictionary]]). This wiki uses backpressure to mean deterministic checks only. See [[backpressure]].
10. **When is a dark factory acceptable?** Huntley says maintainability by humans is optional. Pocock and Osmani say human review is the main safeguard. See [[software-factory]].
11. **Flat plan vs API pricing.** How does a subscription plan (Pocock's 5x Max) change loop design compared with pay-per-token APIs? See [[budgets-and-cost]].
12. **Human merge gate.** Tan's Autopilot-full merges on a fresh verifier swarm's clean verdict, while benny is draft-only ([[src-tan-pstack-guide-overnight]], [[src-tan-benny-automation]]). Pocock and Osmani keep humans on PRs. What evidence justifies removing the human? See [[software-factory]] and [[earned-autonomy]]. *Data point (2026-10-19):* robomp opens PRs at volume (2,773, ~81% merged), but another account merges them, often in batches ([[src-omp]]). *Data point (2026-10-27):* the Claude Code team scales the gate by risk (0, 1 or 2 humans) and justifies relaxing it with metrics: human approvals and wait time down, revert and incident rates not up. Merged PRs more than doubled while the revert share fell by more than 40% (self-reported, [[src-osmani-claude-code-code-review]]). See [[layered-code-review]].
13. **Worktrees or cloud agents** for parallelism ([[src-tan-complete-guide-pstack-pt1]] vs [[src-osmani-loop-engineering]])? See [[isolation]].
14. **Cap or pivot?** Iteration caps (Pocock) vs "a plateau means pivot, not stop" plus a time-based escape hatch (Tan). See [[termination]].
15. **Source bias.** Tan's Cursor material comes from a Cursor employee, now at xAI ("SpaceXAI" per an unverified report), and her throughput claims are self-reported. A third-party report finds them inconsistent: ~1,000, ~2,000 and 2,500 PRs/month in different places ([[src-inside-pstack-report]]).
16. **Model-family vs context diversity.** Is cross-family review (pstack) materially better than a same-model checker with fresh context (Pocock, Claude Code ports)? No source measures it ([[src-inside-pstack-report]], [[src-pocock-ai-coding-dictionary]]). Ouroboros warns that vote labels don't prove independent vendors ([[src-ouroboros]]). See [[evaluator-optimizer]].
17. **Does maintainability still matter?** Tan (11 Oct 2026) says it is *"no longer true"* that it does, yet pstack ships a minimize-reader-load principle and `/architect` designs for the next agent reader ([[src-inside-pstack-report]]). Compare Huntley and Pocock on the dark factory. See [[software-factory]] and [[agent-experience]].
18. **Cost of rigor.** Is pstack's roughly 2× wall-clock and token cost (one anecdotal test) worth its catch rate (3 false claims)? No systematic comparison exists ([[src-inside-pstack-report]]). See [[budgets-and-cost]].

19. **Shared memory graph vs fresh context.** [[agentos]] offers a persistent, cross-tool knowledge graph as agent memory ([[src-agentos-docs]]). Fresh-context loops deliberately keep state small and per-repo ([[src-pocock-ralph-plugin]]). Does a big shared memory help loops, or does it bring back stale context? See [[context-and-state]].
20. **Big refactors vs small steps.** AgentOS: *"Blast radius is not a cost"* (pre-launch) ([[src-agentos-docs]]). Every loop source biases toward small units. Is the difference about change size vs iteration size, or about project stage? See [[task-sizing]].
21. **LLM judge or deterministic wake?** OpenProse retired its *"judge → verdict → pressure → fulfillment loop"* in favour of a fingerprint reconciler with *"no LLM in the wake/commit decision"* ([[src-openprose]]). `/goal` puts a fresh-model judge in exactly that place ([[src-osmani-loop-engineering]]). Why was the judge removed, and does the reason carry over to one-time goal loops? See [[reconciler-loop]] and [[decision-step]].
22. **Independence: rule or requirement?** OpenProse lets the executor and evaluator share an agent unless a contract requires independence ([[src-openprose]]). pstack forbids self-judging outright ([[src-tan-pstack-guide-verify-and-ship]]). See [[evaluator-optimizer]].
23. **Self-audit or separate judge at the stop gate?** omp's `/goal` lets the doer call `complete` after a structured audit, with an optional advisor shadowing every turn ([[src-omp]]). Claude Code and Codex `/goal` reportedly use a separate model at the gate ([[src-osmani-loop-engineering]]). Which catches more premature "done"s? See [[goal-loop]].
24. **How deep is human review in a high-volume factory?** robomp's merged PRs often land in batches ([[src-omp]]). Is that review, or rubber-stamping? Pocock's *"Reading the diff counts"* sets the bar ([[src-pocock-ai-coding-dictionary]]). See [[software-factory]] and [[operator-debts]].
25. **Should the doer see the grader?** Ouroboros hides the grading commands and assertions from workers on principle ([[src-ouroboros]]). Pocock and Tan have the agent run its own checks ([[src-pocock-ralph-tips]], [[src-tan-pstack-guide-verify-and-ship]]). Is the right split "own checks visible, acceptance gate hidden"? See [[verification]].
26. **May a loop rewrite its own spec?** Ouroboros's Reflect changes the ACs between generations without a human ([[src-ouroboros]]). Tan and omp forbid relaxing the finish condition ([[src-tan-pstack-guide-overnight]], [[src-omp]]). When is spec evolution learning, and when is it moving the goalposts? See [[evolutionary-loop]].
27. **May a model clear a change?** The Claude Code team lets automated review plus green checks merge a low-risk change with no human ([[src-osmani-claude-code-code-review]]). Ouroboros says models may only *withhold* acceptance ([[src-ouroboros]]), and Pocock calls automated review a filter, not a gate ([[src-pocock-ai-coding-dictionary]]). Is a risk classifier plus fast rollback enough to make model clearance safe? And who checks the classifier? See [[layered-code-review]] and [[verification]].
28. **Circuit breakers.** Should approval requirements tighten automatically when revert or incident rates rise? The Claude Code team doesn't have this yet and is *"looking into"* it ([[src-osmani-claude-code-code-review]]). No source describes one. See [[rollback-and-recovery]].
29. **Who owns convergence in a maker/checker loop?** The Claude Code team put the fix mostly on the *checker* (report bug classes, don't re-report, re-review only the diff) ([[src-osmani-claude-code-code-review]]). AgentOS reads non-convergence as a bad *problem* ([[src-agentos-docs]]), and Ouroboros detects oscillation in the *spec* ([[src-ouroboros]]). See [[evaluator-optimizer]].
30. **One window or many?** Anthropic's Applied AI team says a single loop with shared context and [[progressive-disclosure]] often beats multi-agent designs on quality, cost and latency, keeping subagents only for measured bloat, parallel fresh-window work, or tool and instruction conflicts ([[src-anthropic-fold-subagents]]). Huntley and Tan push bulk work *out* of the main window to subagents ([[src-huntley-ralph]], [[src-tan-pstack-loop-principles]]). Is the dividing line inner loop vs outer loop, interactive vs unattended, or just model generation? No source measures both on the same task. See [[folding-subagents]] and [[smart-zone]].
31. **Is the post-answer verifier optional?** Anthropic's single loop treats a goal or verifier check after the answer as optional ([[src-anthropic-fold-subagents]]); loop engineering treats a separate checker as the condition for walking away ([[src-osmani-loop-engineering]]). See [[evaluator-optimizer]].
32. **Does scaffolding expire?** Anthropic says each new model lets more decision-making move from harness into model, and that old-model rules make agents slower or more rigid ([[src-anthropic-fold-subagents]]). omp says *"the harness is the variable"* ([[src-omp]]), and OpenProse moves the outer decision *into* code ([[src-openprose]]). Which harness parts are permanent (budgets, gates, mechanical code) and which are model-era crutches? See [[decision-step]] and [[build-the-lever]].

# Backlog triage (making work agent-ready)

Before an AFK loop can pick up work, someone has to turn messy inbound issues into **agent-ready briefs**. Pocock's `triage` skill does this with a state machine. It is HITL by design: it *"recommends and then waits"* ([[src-pocock-triage-skill]]). Osmani's morning automation is the scheduled, agent-driven counterpart, triaging CI failures and issues into a board ([[src-osmani-loop-engineering]]). See [[scheduled-loop]]. Up: [[practice]].

## State machine
Each issue gets exactly one category (`bug` / `enhancement`) and one state ([[src-pocock-triage-skill]]):

| State | Meaning |
|---|---|
| `needs-triage` | the default landing state |
| `needs-info` | waiting on the reporter |
| `ready-for-agent` | fully specified, brief attached, **an AFK agent can take it** |
| `ready-for-human` | same brief, plus why an agent can't do it (judgment, access, manual testing) |
| `wontfix` | closed with the reason. Rejected enhancements get a concept file in `.out-of-scope/`. |

## Practices worth copying
From [[src-pocock-triage-skill]]:
- **Verify before you brief:** reproduce the bug, or run the PR's tests. Check whether it is already implemented (search by concept) and whether it was rejected before.
- **Durable briefs:** name types, signatures and behaviours, *never* file paths or line numbers, because tickets wait weeks while the code changes. See [[goal-spec]].
- **Label AI output:** every comment starts *"This was generated by AI during triage."* See [[observability]].
- **`ready-for-agent` is the handoff point** between human triage and the [[software-factory]]. An issue labelled that way is a trigger.

## Automated variant (Tan's benny)
Triage runs as an **event-triggered automation** on each Slack report. It analyses screenshots and videos, deduces which feature is meant, checks the reporter's version, searches duplicates, and files a ticket only for clear net-new bugs. Its one-line verdict marker then **triggers the repro automation** ([[src-tan-benny-automation]], [[src-tan-loops-you-can-trust]]). Compare Pocock's skill, which is human-invoked and recommends and then waits. See [[stage-gated-pipeline]].

## Failure modes
From [[src-pocock-triage-skill]]:
- Bulk runs that rely on the cheap listing (no comments) briefed three already-fixed issues.
- With no `blocked` state, AFK agents pick up `ready-for-agent` items that depend on other work.
- With no `implemented` state, *"an AFK runner can queue finished tickets again."*

See [[failure-modes]].

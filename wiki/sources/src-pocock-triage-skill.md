# Pocock — "triage: Turn Backlog Mess Into Agent-Ready Work" (2026-05-05)

**Author:** [[matt-pocock]] · **Raw:** `raw/2026-10-12-pocock-triage-skill.md` · Up: [[sources]]

## Summary
A human-invoked skill that moves **incoming** issues (not ones you wrote) through a small state machine. Each issue gets one category (`bug` or `enhancement`) and one state: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` or `wontfix`. It **recommends, then waits**, and nothing is applied until you say so. The output is an **agent brief** that AFK runners pick up. See [[backlog-triage]].

## Key claims
- **Verify before you brief:** reproduce the bug or run the PR's tests. It also checks for redundancy (already built?) and prior rejection (`.out-of-scope/`, matched by concept).
- **Briefs are durable, not precise:** they name types, signatures and behavioural contracts, never file paths or line numbers, because issues sit for weeks while the code changes. See [[goal-spec]].
- **Two lanes meet at `ready-for-agent`:** the triage lane for inbound work, and the spec → tickets → implement lane for your own work. See [[software-factory]].
- **Known gaps:** there is no `blocked`, `deferred` or `implemented` state. Without `implemented`, *"an AFK runner can queue finished tickets again."* See [[failure-modes]].
- **Bulk-run pitfall:** the cheap listing omits comments, so three already-fixed issues got new agent briefs. See [[failure-modes]].
- Every comment it posts starts with *"This was generated by AI during triage."* See [[observability]].
